# 租户配置包迁移

租户配置包用于把一个租户的管理配置迁移到另一个环境或另一个租户。所有租户仍运行同一套编译后的业务代码；配置包不会安装插件、脚本、动态 Rust 模块或租户专用处理器。

## 1. 范围与安全边界

配置包只包含部门、岗位、字典类型和字典数据、明确标记为可迁移的参数、权限、菜单、普通角色、角色权限和角色自定义部门范围。用户、密码、用户角色、日志、文件、消息、公告、后台任务、Cron、服务账号、API Key、Secret、Token、证书、应用 TOML 和环境变量永远不进入配置包。

包格式固定为 `*.ryframe-config.zip`，ZIP 根目录只能存在：

```text
manifest.json
resources.json
```

服务端会拒绝额外或重复文件、目录、符号链接、加密 ZIP、路径穿越、不支持的压缩算法、超过容量上限的内容、异常压缩比、过深 JSON、项目数超限以及 SHA-256 不一致。SHA-256 只验证传输完整性，上传包仍被视为不可信输入并执行完整目标端校验。

## 2. 稳定业务键

配置包不保存数据库 ID：

- 部门使用从根开始的名称片段数组，例如 `["总公司", "研发中心", "平台组"]`。
- 岗位使用岗位代码。
- 字典类型使用类型代码，字典数据使用类型代码和字典值。
- 参数使用参数键，且必须显式启用“允许配置包迁移”。
- 权限使用权限代码，父级使用父权限代码。
- 目录和页面使用 `route_key`；操作菜单使用父菜单稳定键和权限代码。
- 角色使用角色代码；超级角色不迁移。

部门完整路径重复、部门或菜单存在循环和缺失父级、目录或页面缺少 `route_key`、角色引用不存在资源、超级通配权限、敏感参数被错误标记为可迁移时，导出或上传会安全失败，不会猜测数据库 ID 或选择第一条记录。

## 3. 管理流程

1. 在来源租户生成配置包，或上传此前下载的配置包。
2. 查看来源租户快照、协议版本、应用版本、SHA-256 和资源数量。
3. 显式执行预览。预览从目标主库读取配置版本和授权纪元，并把项目分为 `create`、`update`、`unchanged`、`conflict` 和 `blocked`。
4. 修复所有 `blocked` 项后重新预览。
5. 核对预览的计划哈希、目标配置版本和目标授权纪元后，显式确认应用。
6. 应用成功后，在回滚截止时间前按需执行回滚。

应用只创建缺少资源、更新稳定键相同的资源并跳过相同内容。目标租户独有资源不会被删除或停用；只有包中明确出现的角色会替换其权限和自定义部门集合。

迁移记录创建后的初始状态是 `preview_ready`，表示可以提交首次预览；预览入队以及自动或人工重试等待期间是 `preview_pending`，Worker 开始计算后是 `previewing`，成功后是 `previewed`。这样“尚未提交预览”和“预览已经排队”不会共用同一状态。

## 4. 并发、失败与回滚

预览不会修改配置。应用和回滚会先取得目标租户独占配置租约；租约有效期间，部门、岗位、字典、可迁移参数、权限、菜单、角色及其关系的普通写请求返回 `409`。最终写事务会重新核对计划哈希、配置版本、授权纪元、申请人状态与权限，任一变化都会停止写入。

应用前会生成目标配置快照并写入私有 `config-packages` Bucket。快照上传失败时不会修改数据库；数据库应用在一个事务中执行，失败时整体回滚。成功后递增配置版本，涉及授权时同时递增授权纪元，并通过现有缓存版本和授权通知生效。

回滚默认窗口为 168 小时。只有当前配置版本和授权纪元仍等于应用完成版本、快照仍存在、本次创建资源未产生新引用且相关资源没有后续人工修改时才能回滚。回滚不删除用户、业务数据或目标端原有独立资源，也不提供部分回滚。

## 5. 部署和保留

部署顺序固定为：

```text
数据库迁移
  → 能识别配置迁移任务的新 Worker
  → API
  → 前端
```

API 和 Worker 必须使用相同的 `[tenant_config_transfer]` 配置并在修改后同时重启。配置包文件到达 `artifact_hours` 后进入安全对象清理，快照在回滚窗口结束后进入安全清理；配置包和迁移元数据保留用于审计，不在没有明确历史保留策略时自动硬删除。

任务载荷只保存配置包或迁移记录 ID，不保存包内容、对象路径或敏感数据。MySQL 是任务和迁移状态的事实来源，Redis 只负责降低任务唤醒延迟。
