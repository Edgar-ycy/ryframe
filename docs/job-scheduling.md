# 定时任务使用与维护

RyFrame 的定时任务不是任意代码执行器。管理端只能选择后端注册的安全目标，不能填写 Shell、URL、
Rust 函数名或任意 JSON。当前内置目标只有系统租户可用的“导出结果过期清理”和“消息过期清理”；
普通租户只有在业务模块注册租户级目标后才能创建计划。

## 使用可视化规则生成器

1. 进入“系统监控 → 定时任务”，选择“新增计划”。
2. 选择执行目标。
3. 在执行周期设置中选择每隔几分钟、每隔几小时、每天、每周、每月或每年。
4. 填写时间、星期或日期；页面会自动生成七段 Cron 表达式，不要求用户学习表达式语法。
5. 选择 IANA 时区。默认使用浏览器时区，无法识别时回退为 `UTC`。
6. 核对自然语言摘要，以及服务端返回的最近五次执行时间。每行同时显示计划时区、浏览器本地时区和
   UTC 时间，计算基准使用数据库当前时间。
7. 最近五次时间通过服务端校验且仍与当前规则一致后，才能确认保存。

规则、时区变化后，旧预览会立即失效；页面停止输入 500 毫秒后自动重新计算。也可以点击“重新计算
最近时间”，以新的数据库当前时间立即计算。网络失败不会清除用户输入，但在预览成功前不能保存。

每月选择 29、30、31 日时，没有该日期的月份会跳过，不会自动改为月末。每年 2 月 29 日只在闰年
执行，2 月 30 日、4 月 31 日等无效组合无法通过生成器或服务端校验。

## 高级七段 Cron

高级模式的字段顺序固定为：

```text
秒 分 时 日 月 周 年
```

- 秒字段只能是 `0`，最小执行间隔为一分钟。
- 年字段只能是 `*`。
- 日期字段和星期字段不能同时受限，其中一项必须为 `*`。
- 星期使用 `MON TUE WED THU FRI SAT SUN`。
- 时区必须是有效的 IANA 名称，例如 `UTC` 或 `Asia/Shanghai`。
- 最终解析、时区校验和未来五次时间都以服务端结果为准。

夏令时开始时，不存在的本地时间会跳过；夏令时结束时，重复的本地时间可能对应两个不同 UTC
时刻。使用夏令时时区时，应重点核对最近五次预览中的三列绝对时间。

解析和时区实现分别参考 [`cron::Schedule`](https://docs.rs/cron/0.17.0/cron/struct.Schedule.html)
与 [`chrono-tz`](https://docs.rs/chrono-tz/0.10.4/chrono_tz/)。日期和星期组合语义的背景见
[`cron` issue #141](https://github.com/zslayton/cron/issues/141)。

## 运行开关

```toml
[jobs]
scheduler_enabled = true
```

生产环境可使用 `APP_JOBS_SCHEDULER_ENABLED=true` 覆盖。该值只控制 Cron 管理、路由、菜单和扫描，
不控制通用后台任务 Worker。修改后必须同时重启 API 和独立 Worker，不支持运行中热切换。

设置为 `false` 后：

- 定时任务菜单和 `/api/v1/monitor/schedules/**` 路由不可用。
- Embedded、External 和 `ryframe-worker --once` 都不扫描计划。
- 普通后台任务、Outbox、导出、消息、重试和死信继续运行。
- 已经入队或正在执行的计划任务继续完成。
- 计划、权限、菜单记录和历史保留在数据库中。

重新启用并重启后，原计划恢复可见，并按各自的 `skip` 或 `fire_once` 策略处理关闭期间错过的触发，
不会逐条补跑全部历史。

## 增加安全调度目标

新增业务目标时，实现 `ScheduledJobTarget`，声明稳定的 `handler_key`、租户范围、后台任务类型、
可用状态、优先级、重试次数和安全载荷生成逻辑。随后通过应用启动层的共享装配入口同时注册目标和
对应 `JobHandler`。Embedded、External 和 `--once` 共用同一处理器装配，并在启动前校验每个可用
目标都有处理器；重复目标、重复处理器或缺少处理器会直接拒绝启动。

不要从前端接收处理器函数、命令、URL 或内部任务参数，也不要在 `JobQueue` 中引用 Cron 服务。

## 后期移除 Cron

1. 设置 `APP_JOBS_SCHEDULER_ENABLED=false`。
2. 同时重启 API 和 Worker。
3. 确认菜单、接口和扫描都已关闭，普通后台任务仍正常。
4. 观察至少 24 小时。
5. 删除调度服务、目标注册表、API、前端页面、生成器、调度配置、指标、告警和旧每日调度兼容模块。
6. 默认保留数据库历史；如需彻底清理，新增前向迁移，不修改旧迁移。
7. 保留 `JobQueue`、`JobWorker`、Outbox、导出、消息、租约、重试和死信。
