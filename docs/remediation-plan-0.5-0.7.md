# RyFrame 0.5.0–0.7.0 分阶段整改追踪

本文以《RyFrame 0.5.0–0.7.0 分阶段整改计划》为唯一范围。状态含义：

- `已完成`：实现与对应自动化验证均已具备。
- `部分完成`：已有基础实现，但尚缺计划要求的能力或验收。
- `未开始`：尚未发现实现或验收证据。
- `待核验`：实现存在，但尚未完成计划要求的运行环境验证。

## 0.5.0：工程闭环

| 条目 | 状态 | 当前证据与剩余工作 |
| --- | --- | --- |
| 工作流、编码与仓库卫生 | 部分完成 | 后端已在隔离 MySQL、Redis、RustFS 上通过全工作区测试、doctest 与 Clippy；前端已通过完整 `pnpm check`。干净双仓克隆已分别通过后端全工作区构建检查，以及前端锁定依赖安装、OpenAPI 契约、类型和生产构建验证；仍需托管 CI 的完整复现证据。 |
| 稳定版联合发布 | 部分完成 | 后端发布工作流与 `release-manifest.json` 已存在；尚未完成正式稳定标签的双仓发布演练。 |
| 固定来源 OpenAPI 契约 | 部分完成 | 前端已记录来源 SHA 并支持本地/上游校验；需在后端提交后完成上游固定来源校验。 |
| 开发工具链与 `xtask` | 部分完成 | 工具链、`xtask` 和统一配置入口已具备；仍需在干净环境验证全部子命令后工作区无差异。 |
| 0.5 发布验收 | 部分完成 | 本地后端全工作区门禁、前端完整门禁与干净双仓构建复现均已通过；仍未完成双仓稳定标签和托管 CI 矩阵验收。 |

## 0.6.0：正确性、安全与可维护性

| 条目 | 状态 | 当前证据与剩余工作 |
| --- | --- | --- |
| 统一 API 响应与分页契约 | 已完成 | 已切换为 `message/data/request_id/error_key/details`；分页数据统一为 `data.items/page/page_size/total/total_pages/max_page_size`，并完成 OpenAPI 与前端类型同步。 |
| 安全、Markdown 与幂等 | 部分完成 | Markdown 安全渲染、分页、幂等和统一错误载荷已具备；仍需按计划补齐其余专项验收。 |
| 增量迁移与独立 Worker | 部分完成 | 迁移、任务表、独立 Worker 与生产外置限制已具备；`sys_outbox_event` 已实现事务写入、租约领取、退避重试、死信及与后台任务原子投递，`ryframe-worker --once` 可用于单轮演练。过期租约回收已与并发领取事务解耦，避免 MySQL 锁顺序冲突。Worker 会在执行时复核任务创建者当前权限与数据范围；所有导出资源均已改为稳定主键游标批处理，仍需完成正式切换演练。 |
| 后台导出与通用任务接口 | 部分完成 | 用户、角色、岗位、参数配置、字典类型、操作日志和登录日志已统一为 `POST /system/{resource}/exports`，创建请求必须携带 `Idempotency-Key` 并返回 `202`；任务统一从 `/common/jobs` 查询、取消和受控下载，结果 24 小时过期清理。前端已由后端 OpenAPI 快照重新生成类型，并完成创建、轮询和下载交互；所有资源均已覆盖 Worker 回归测试和主键游标批处理。 |
| 权限快照、缓存与文件完整性 | 部分完成 | 版本化权限缓存、SHA-256 与文件回填已具备；需补齐计划规定的完整运行验证。 |
| 前端数据层、错误处理与可访问性 | 已完成 | TanStack Query、会话恢复、安全渲染、真实 CRUD 与运行时动态权限路由均已落地；完整质量门禁已通过 45 个单元测试、14 个端到端测试和覆盖率阈值，登录后工作台已纳入 WCAG 2.0 A/AA axe 自动验收。主题色会派生可读文本色，避免自定义浅色主题破坏对比度。 |
| 0.6 发布验收 | 部分完成 | 已在隔离 Docker MySQL、Redis 与 RustFS 上完成数据库重置迁移；外置 API 与独立 Worker 均通过就绪检查，22 项运行时冒烟（含异步导出与下载）通过，验收日志无告警或错误。仍需完成 API/Web 正式切换、故障恢复及前端专项验收。 |

## 0.7.0：架构与正式扩展能力

| 条目 | 状态 | 当前证据与剩余工作 |
| --- | --- | --- |
| Crate 边界与最小依赖 | 部分完成 | `kernel`、`i18n`、`excel`、`mail` 等拆分已存在；需完成剩余依赖方向和最小特性矩阵验收。 |
| i18n、OTel、URL 版本与读副本 | 部分完成 | 双语、语言协商、OTel、`/api/v1` 与读一致性选择已实现；需完成计划要求的端到端和故障验收。 |
| 通用消息中心 | 部分完成 | 消息表、票据、收件箱、ack/read 与前端连接已具备；需改为 Query 保存服务端消息数据，并完成双 API 实例真实链路验证。 |
| OCI、SBOM、签名与生产 Compose | 部分完成 | 发布工作流已定义 GHCR `linux/amd64`/`linux/arm64` OCI 索引、Buildx provenance、SPDX JSON SBOM、Cosign OIDC 无密钥签名和签名验证；`release-manifest.json` 已升级为 v2 并记录不可变镜像摘要与证明类型，生产 Compose 已将 API、迁移和独立 Worker 与外部托管依赖分离。仍需在托管发布环境完成真实镜像推送、签名和升级演练。 |
| 0.7 发布验收 | 未完成 | 尚未完成双实例消息、读副本故障、供应链签名与升级演练。 |

## 执行顺序

1. 收口 0.5 双仓契约与干净克隆发布演练。
2. 完成 0.6 统一响应契约，再实施 Outbox、导出任务和 Worker 验收。
3. 完成 0.6 前端与生产切换验收。
4. 收口 0.7 架构、i18n、OTel、读副本与消息中心的运行验收。
5. 验证 0.7 OCI、SBOM、Cosign 和生产交付，完成稳定版联合发布演练。
