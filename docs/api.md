# API

[English](api.en.md)

登录、刷新及 `/auth/context` 使用同一 `SessionContext`，必须包含布尔型 `password_change_required`。该值为真时，超级管理员标志为假，角色、权限、菜单和能力集合为空；受限令牌只能读取会话上下文、修改自己的密码和退出，不能签发消息票据。成功改密清除标志、更新授权版本并撤销该用户的登录会话，客户端重新登录。

受限会话按 HTTP 方法及原始完整路径核对：仅允许 `GET /api/v1/auth/context`、`PUT /api/v1/auth/profile/password` 和 `POST /api/v1/auth/logout`，嵌套路由不改变此限制；其他业务接口及消息票据仍被拒绝。

授权诊断区分缓存 `current`、`behind`、`ahead`、`missing`、`disabled` 与 `unavailable`。镜像落后于新令牌时，从主库验证身份后原子重建；镜像版本更高时旧令牌仍被拒绝，不向后覆盖缓存。缓存关闭是正常配置状态，不作为缓存故障警告。

## 异常账号恢复

初始管理员密码通过明文配置 `[bootstrap] admin_password` 显式提供；新建、导入和初始化的普通用户使用 `123456` 并在首次登录后强制改密；已有账号不会在启动或重复初始化时重置。如果旧开发版账号保存了未知密码，管理员先完成自己的首次改密，再在用户管理选择该普通用户的密码重置操作，填写原因并生成一次性链接。用户打开链接后自行设置符合复杂度要求的新密码，再重新登录。此流程不适用于超级管理员，不直接改写数据库中的密码哈希。

重置请求最长有效 24 小时且只能消费一次。成功重置或自助改密在同一事务中更新密码、清除改密标志、递增授权版本，并使该用户其余待处理重置请求立即过期；旧访问令牌和刷新令牌因此失效。同一用户的并发重置只有一个能完成，其他用户的请求不受影响；后续明确新建的重置请求仍可使用。重置不会自动启用停用账号，管理员须另行启用；单独启用账号不会清除首次改密要求。单租户重置固定使用系统租户，多租户链接保留目标租户标识，不能借另一个租户的链接完成重置。

## 契约入口

HTTP 接口使用 `/api/v1` 前缀，完整路径、字段和 operation ID 见 `openapi/openapi.json`。开发环境启用 `api_docs.enabled` 并编译 `runtime-swagger-ui` feature 后，可访问 `/api/v1/swagger-ui`；原始文档位于 `/api/v1/api-docs/openapi.json`。

调用方应使用当前契约生成的 `core/system/platform/monitor` 四域 caller。开发版本的接口变化需要同步更新调用方，不提供旧结构映射。

新配置默认关闭多租户；`GET /api/v1/version` 的 `multi_tenancy_enabled` 是客户端运行模式依据，获取失败应重试。单租户身份固定为 `system`，不开放租户和套餐管理路由，会话菜单同步排除这些页面；配置包、配置迁移及数据维护继续开放，并保持系统租户和权限校验。显式开启多租户后，租户管理、套餐分配和租户选择恢复可用。

普通业务端点使用 JSON；上传、文本、验证码图片、Blob 和文件下载按 OpenAPI 声明的 media type 传输，调用方不得把这些响应按 JSON 解码。时间使用带时区的 RFC3339 并在服务端规范化为 UTC。JSON DTO 默认拒绝未知字段；非法枚举、反向时间范围和越界批量请求在入队前返回 400。

ID 始终使用字符串传输。精确 Decimal 字段同样只接受十进制字符串，例如 `"0.125000"`；整数和小数位数由模型的 `DECIMAL(p,s)` 决定，超过容量会拒绝，禁止经过浮点数或自动舍入。业务生成器中声明为字符串传输的 `i64/u64` 字段，其正文、查询和响应均使用规范十进制字符串，例如 `"9007199254740993"`；正文不接受 JSON 数字，禁止先经过 JavaScript Number 再转换。无符号业务主键的 URL 参数同样保持规范十进制和完整 u64 范围。这些业务整数字段会拒绝前导零、加号、负零、小数、空白或越界值。可选字段允许省略或传 null，业务默认值及可空更新语义以当前模型和 OpenAPI 为准。

上传同时遵守配置中的文件大小与请求体上限，分块传输同样受限，不叠加 Multipart 提取器的默认 2 MiB 限制。畸形上传表单返回 400，大小超限返回 413，底层读取故障返回 500。

JSON 业务响应使用统一包络，下面展示中文本地化响应样例；文本和二进制响应直接使用契约声明的 content type，不附加 JSON 包络：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "request_id": "01K...",
  "error_key": null,
  "details": null
}
```

## 认证与授权

`auth.access_token_expire` 与 `auth.refresh_token_expire` 支持小写 `h`、`m`、`s` 或纯数字秒，例如 `"1h"`、`"30m"`、`"45s"`、`"3600"`；忽略首尾及数字与单位之间的空白，不接受 `"7d"` 或大写单位。非法格式、数值或换算溢出，以及有效期与当前时间相加超出平台可表示范围，都会使认证设置构造返回配置错误，指出对应字段与修复方法。请修正所选环境文件中的字段或减小有效期；签发时仍会复核时间相加，CSRF 的 `ttl_seconds` 参数过大也返回可定位错误，不回显密码或 JWT 秘密。

服务端通过唯一项目环境入口 `APP_ENV` 选择 `dev`、`test` 或 `prod`；`config/app.toml` 是公共默认值，所选 `config/app.<environment>.toml` 必须存在。JWT 密钥直接填写 `auth.jwt_secret`，指标凭据直接填写 `monitor.metrics_bearer_token`；认证、数据库连接（含主库、副本与命名数据源）及监控配置的 `Debug` 会隐藏 JWT 密钥、数据库密码、TLS 客户端私钥与指标令牌；原始配置和连接 URL 仍不得进入日志或公开收据。应用通过 `--config-dir <directory>` 选择目录，默认 `config`，相对路径以当前工作目录解析。客户端不取得这些服务端凭据。本地化目录由 TOML 的 `app.locales_dir` 显式指定，默认 `locales`，普通应用相对进程当前工作目录解析，不读取 `APP_LOCALES_DIR`；资源缺失或加载失败时生产严格拒绝启动，开发环境可内嵌回退。配置与本地化的局部验证不代表 API 整体门禁通过。

先请求 `/api/v1/auth/csrf` 获取 CSRF token，登录、刷新和退出等会话写操作在 `X-CSRF-Token` 请求头中携带它。登录和刷新响应都包含短期 access token 及同构的 `SessionContext`，`GET /api/v1/auth/context` 也返回同一会话快照；长期 refresh token 由 HttpOnly Cookie 保存。受保护接口使用：

```http
Authorization: Bearer <access_token>
```

客户端应原子应用 `SessionContext` 中的用户、租户、角色、权限、授权与运行 epoch、capability 和菜单投影，不得混用不同响应的会话字段。会话上下文显式返回 `is_super_admin`；客户端使用该字段和授权投影展示界面，不根据角色 code 推断超级管理员。服务端认证主体保留构造时的用户授权版本和租户授权 epoch；快照内外版本不一致时拒绝该快照，不用后来读到的版本覆盖旧主体。消息票据签发同时核验主体与访问令牌的用户授权版本。

套餐版本允许空能力集合，租户仍可开通并保留认证和基础资源。公告管理与租户主动消息发布受编译能力目录和有效套餐共同约束，其他基础管理 API 继续遵循 RBAC；普通租户的权限通配符不能打开已关闭的能力，也不能使用平台专属接口。

能力目录的变体返回完整 `config_schema`，首批变体只接受空对象。公告投递到消息中心同时要求公告与主动消息能力；收件箱、已接受消息投递和系统任务通知不受主动消息开关影响。

配置迁移属于平台管理。系统租户操作者通过 `/api/v1/platform/tenants/{tenant_id}/config-packages` 和 `/api/v1/platform/tenants/{tenant_id}/config-transfers` 明确指定资源所属租户；`tenant_id` 是配置来源或应用目标，操作者仍以系统租户身份完成授权和后台复核。配置包会过滤平台、租户管理、通配权限和未开通能力。

每条路由在访问目录中声明一种策略：

- `Public`：无需登录。
- `Authenticated`：需要有效会话。
- `Permission`：需要生成的权限码。
- `Capability`：需要当前部署和租户同时启用能力。

前端缺权限进入 403，已知页面缺 capability 进入“功能不可用”，未知页面进入 404。

已登录用户通过 `GET /api/v1/common/shell-settings` 读取当前租户的侧栏主题和皮肤。该接口只返回固定的界面设置，不接受配置键；缺失项目返回 `null`，客户端使用默认值。按键读取任意配置仍需配置管理权限。

## 错误

错误响应包含稳定错误码、可展示信息和请求追踪信息。调用方应按 HTTP 状态和错误码处理，不解析中文文本。

统一错误包络的 `details.reason` 只公开白名单原因：`invalid_parameters`（请求参数无效）、`captcha_invalid_or_expired`（验证码无效或已过期）、`fixed_tenant_required`（必须使用固定租户）和 `system_tenant_required`（必须使用系统租户）。前端优先使用已知 reason 的本地化译文；reason 未知或缺失时回退到 `error_key` 对应译文，不解析服务端消息来猜测原因。认证与数据库内部原因不公开，也不通过此字段透传。

- 400：请求或状态转换无效。
- 401：未认证或会话失效。
- 403：权限或租户能力不足。
- 404：资源不存在、越权或已删除。配置了 `owner_field` 的标准资源在列表、详情、编辑和删除中使用同一数据范围；写入在当前业务事务内按范围锁行，范围外记录不返回存在性信息。控制库中的范围敏感读取使用主库，避免副本中的旧用户或部门关系放宽范围。
- 409：资源状态冲突。
- 413：导出匹配行数或请求体超过限制。
- 501/503：部署能力不可用或依赖暂时不可用。

租户业务读写的数据范围投影缺失、尚未就绪或版本与控制库权威版本不匹配时，拒绝读写并返回 HTTP 503、`error_key=tenant_data_target_unavailable` 和 `Retry-After: 5`。这表示业务数据暂不可用，应等待投影同步后重试；刷新登录会话不能修复投影落后。该情况不使用表示产品运行代次变化的 `stale_runtime_epoch`。

## 租户套餐变更

提交套餐变更时，传入本次预览返回的 `plan_hash` 和 `preview_runtime_epoch`。服务端校验分配与覆盖权限，并在事务中核对租户运行代次和目标套餐版本。预览过期时重新预览后再提交。

提交与当前版本和规范化覆盖相同的配置时，服务端仍记录成功操作审计。省略 `reason` 时沿用原分配备注，传入不同的原因时只更新这条备注。响应返回当前产品上下文及原有代次。切换套餐版本或变更覆盖时，服务端更新运行代次并通知客户端刷新租户上下文。

## 公告并发编辑

编辑前通过 `GET /api/v1/system/notices/{id}` 读取详情，保留该次返回的 `revision`。使用 `PUT /api/v1/system/notices/{id}` 保存时，将这份版本作为必填的 `expected_revision` 一并提交。两个字段都使用十进制字符串。

服务端在已授权的事务内检查版本。保存成功后版本加一。若公告已被另一位编辑者更新，服务端返回 HTTP 409，保留已保存的记录。客户端应保留本地编辑内容，读取最新详情并让编辑者确认如何合并后，再使用最新版本提交。

## 筛选导出

七类导出使用独立强类型请求，统一包络：

```json
{
  "filter": {},
  "confirm_all": false,
  "ids": ["101", "102"]
}
```

请求不接受 `page` 或 `page_size`。勾选行时传入字符串主键 `ids`，只导出选中且符合最后一次成功应用筛选和数据权限的记录；最多传入 1000 个 ID，重复 ID 会归一化。列表的全选只选择当前页，翻页、刷新或切换会话后清空选择。

未勾选时省略 `ids` 或传空列表，按最后一次成功应用的筛选导出全部匹配分页；筛选为空时必须二次确认，并将 `confirm_all` 设为 `true`。

创建时同步完成匹配数、权限指纹和 `upper_id` 快照。Worker 只读取 `id <= upper_id`，后续新增不进入；权限发生任何变化均失败关闭。

稳定错误码包括：

- `EXPORT_ALL_CONFIRMATION_REQUIRED`
- `EXPORT_NO_MATCHING_ROWS`

## 导出记录删除

终态记录单删与批删共用：

```http
POST /api/v1/common/jobs/deletions
Idempotency-Key: <retryable-key>
```

```json
{
  "ids": ["123", "456"]
}
```

ID 排序去重后必须为 1–100 条。整批先校验租户、申请人、终态和 lease，再标记删除；受理后立即从列表、未读和下载接口消失。对象删除失败会在内部重试，记录不会在网页复活。

## 契约验证

OpenAPI 改变后运行 `cargo xtask generate api --write` 刷新前端派生契约，再执行前端消费者自检与浏览器 smoke。若调用方提示 operation 不存在或 DTO 不匹配，先重新同步契约，再检查后端导出的 operation ID。

启用多租户时，登录页通过公开的租户名称搜索选择租户，认证请求传递所选租户标识；单租户模式不展示或请求租户选择。`GET /api/v1/auth/tenants` 支持 `search`、`page` 和 `page_size`，每页最多 50 项，只返回启用且未过期租户的名称与标识；登录时仍重新校验租户状态。
